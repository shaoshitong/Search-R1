## 结论

正式续训的 **187 个普通 outer**：候选 rollout 平均 **820.504秒（13分40.5秒）**，actor 的20次Adam平均 **130.123秒（2分10.1秒）**，记录内的整个outer主流程平均 **1188.809秒（19分48.8秒）**。对应中位数分别为 **799.636秒、120.210秒、1155.292秒**。rollout占总计时 **69.02%**，是actor更新耗时的 **6.31倍**。

这187轮全部实际采样 **2048题×5＝10240条完整候选轨迹**，最终选择 **512题×5＝2560条**做20次全局Adam更新。节点为 **h100-8，八卡H100**。该统计不是A800或HKUST四卡实验。

## milestone额外开销和计时边界

原始timer关系：

`outer主流程 = candidate_fill_seconds + timing_s/step`

`candidate_fill_seconds`涵盖候选的agent生成、检索交互、RNG保存、严格EM筛选、序列化与拼接；2048题轮次为四波，1536题轮次为三波，均不是纯GPU解码。`step`在候选collect之后才开始，涵盖reference、reward/advantage、actor、可能的验证与保存。`update_actor`是完整分布式调用，包含20次Adam及监控/审计，不是单次optimizer kernel时间。

50/100/150等轮日志记录之后还会执行probe refresh，该部分位于上述两个timer之外。日志、部分acceptance与恢复初始化也没有完整独立timer。因此本文精确报告的是**已记录的outer主流程**，不声称等于包含所有边界操作的完整墙钟周期。`candidate_generation_timings`全部为空，无法进一步可靠拆分纯decode与检索各自秒数。
