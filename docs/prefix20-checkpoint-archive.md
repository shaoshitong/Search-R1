# Prefix20 native4 cross-host checkpoint archive core

This core has only local CPU fixture coverage. Actual source/archive transfer and actual checkpoint/CUDA acceptance remain pending. Healthy training runtime source is not hot-edited by this operator.

## Files and validation

- `checkpoint_archive.py`: Python 3.8-compatible standard-library core; no torch, model loading, GPU request, training, transfer, deletion, or restore-target creation.
- `test_checkpoint_archive.py`: 17 tests using small constructed local byte files. The tests exercise all five complete source → archive → source readback chains, exact topology/method/path bindings, file closure, full SHA, source metadata-preserving corruption, source data-link changes after copying, archive corruption, fsync failure, duplicate JSON keys, symlinks, unknown producer fields, absent actor/probe/driver/boundary RNG states, and shared dependency hardlinks.
- `validation.json`: local test result, Python 3.8 grammar check, hashes of the deliverable files. Constructed tests are not actual checkpoint or CUDA recovery acceptance.

The module requires explicit `base`, full 40-character `commit`, 32-character `run_id`, and one of steps `5/50/100/150/200` at every phase. The dedicated `qprobe-teacher-warmup200-prefix20-*` HPC3 namespace supports the independent recovery base. It rejects step 201 and old sigma3/count methods and eight-rank receipts.

The file graph contains every completed-pair producer record, the original receipt itself, eight original data inputs, three pinned initial probe assets, and nine frozen Qwen dependencies. Actual candidate/selector/probe/actor/driver/RNG state bytes stay unchanged. Data symlinks are accepted solely as the six exact official `base/data/<name>` → fixed official DATA links; archived payloads are regular files. All probe ranks and actor rank state files are required, alongside driver state and four separately saved post-evaluation boundary RNG files. Reward head and reward encoder dependencies must exactly close over the pinned reward manifest. All ancestor symlinks, escaping/noncanonical paths, unexpected payload files or empty directories, duplicate source records, and inconsistent bytes/hashes are rejected.

The original producer still owns tensor contents and CPU state validation. The new layer makes full-file SHA and file-placement claims only. Its final status is **`SOURCE_ARCHIVE_FULL_SHA_PASS`**, with `actual_cuda_restore_accepted: false` throughout.

No local Mac staging and no HPC3 archive/target copies. Use durable per-file temporary names and a held transfer exit receipt. Progress means measured verified-byte increments plus successful next phases; controller/PID/Slurm survival alone is insufficient. Do not change or restart the healthy training job while adding the archive controller.

## Storage and recovery constraints

The core creates zero HPC3 checkpoint archives and zero HPC3 restore targets. It keeps the existing five HPC3 sources and places five archives on HKUST3. A future restore controller needs a separate exclusive lock and persistent target registry so **at most one HPC3 restore target** exists at a time.

The current training reserve estimates five actor/probe source pairs plus one temporary restored pair. This core additionally preserves explicit canonical input and frozen-model dependencies on HKUST3. Without hardlink/content-addressed reuse, their bytes are repeated five times; the controller must calculate the true allocated upper bound before copying. With reuse, unique dependency bytes are counted once in HKUST3 capacity. A future HPC3 restore admission must include any newly materialized canonical data/frozen encoder bytes as well as the trained pair. This does not raise the user's 2 TB HPC3 budget.

The archived tensors and original receipts retain their source absolute paths. Actual CUDA restoration must load **copied archive bytes from the single restore target**, not accidentally pass by reading retained original sources. A separate restore-binding manifest must map every original source path to its verified target copy, record target inode/bytes/mtime and source/archive SHA provenance, and account for absolute references inside JSON state manifests. Keep original tensor and receipt bytes unchanged. The existing schema3 probe reader already loads rank states by the checkpoint directory plus recorded basename, but actor worker/driver/reward manifest consumers also need explicit audited mapping; do not assume that copying a directory makes those pointers safe.

Final200 recovery is a standalone restore-only path: initialize four actual workers, restore actor HF/Adam/scheduler/RNG, four probe model/Adam/private RNG states at 2000 optimizer steps, selector/eligible mapping/candidate pending cursor/driver RNG, and make two real readbacks with data equality. It must never call fit/generate/update/save and must leave every update/write counter unchanged. Existing normal-training guards rejecting update201 remain in force. This archive core deliberately cannot assert that acceptance.

The current core's historical receipt pointers must remain inside the explicitly bound source base (plus the fixed official model). If a later resumed training execution inherits historical pointers from a second base, do not relax containment to all experiments. Extend the graph with an independently authenticated source-pair chain and tests, or materialize only those referenced metadata files into the new base before publication. The pristine recovery727000 run being prepared after the failed GPU preflight has no inherited training checkpoint chain.
