The first CPU Prefix80 preparation used a global protocol trajectory-ID lookup across retained source-event inventories. At source 573 it correctly stopped on strict-EM disagreement. Independent recomputation showed the canonical labels were correct: donor and HPC3 executions shared protocol IDs and first20 tokens, but had different actual Prefix80/full responses and valid different EM. No canonical labels or existing training jobs were changed.

Version2 first binds each explicit whole-G5 source-bank chosen execution and physical seal, rejects ambiguous different payloads for all remaining canonical IDs, and joins every selected own_EM to canonical labels. Only the chosen full-payload SHA supplies tokens. The completed resolver covered all 1,690,280 canonical trajectories and excluded 17,920 wrong-execution candidates in 28 files (3,584 questions); 1,718 candidate labels differed across 1,240 questions. Substituting those wrong candidate executions would change 192 G10 Mixed labels (98 Mixed→homogeneous, 94 homogeneous→Mixed). These counts describe rejected candidates, not erroneous historical canonical labels.

The original three failure cases were then found in actual version2 token-shards. All initial-prompt tokens and all 80 retained policy-prefix tokens matched the chosen HPC3 execution exactly, with EM 1/1/0. The old version1 directory and 8 complete chunks were preserved. Version2 has independent code, source publication, process, locks and immutable output root. Compact P20 alignment is a secondary audit; it cannot choose which physical execution is correct. The previously used 8,192-question pilot was separately audited by the scoring agent: all 81,920 own-G10 P80/EM rows matched its actual physical sources, and it has no overlap with the affected HPC3 cohort.
