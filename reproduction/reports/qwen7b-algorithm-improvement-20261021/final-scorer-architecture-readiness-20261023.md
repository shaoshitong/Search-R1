The existing common final loader reconstructs up to80 authentic retained policy tokens from original own journals after an explicit freeze. It can therefore support both Native P80 causal capture and Packed P80 flattening without new trajectories; it must never expand an already truncated Prefix20 record into80. The question/ownG5 identity plan and trajectory EM join stay exactly the same for E1, candidate raw and candidate EMA. Both original independent2048 pools retain their original qid/trajectory-ID ordering and separate results; no new sampling or final-based threshold fitting is allowed.

The current freeze protocol permits one candidate state. To report raw and EMA on the exact same pool, a new freeze descriptor must explicitly predeclare both state keys from the same SHA-accepted checkpoint and choose the primary state from viewed-validation results before unblinding. The other state is a paired diagnostic, not a way to choose a winner on final data. If several architecture leaders are to be reported, their finite list and primary comparison must likewise be frozen beforehand; this inventory does not select or freeze them.

Before any final run, the new immutable scorer needs: metadata-only geometry/architecture rejection tests; exact accepted-checkpoint strict-load acceptance for the declared raw/EMA; source-level token/mask/padding equivalence with the proper training capture; and one fixed viewed2048 equivalence check against already saved training/evaluation predictions. That check uses the viewed token bank only, is not a new training grid, and cannot open the final pools. The same-questions paired Top512/BA/AUC analysis should reselectTop512 in each predeclared paired question bootstrap and preserve deterministic qid tie ordering. Variance and classification thresholds remain family-specific and predeclared.

Existing scorer entries and active training sources are unchanged. A future scorer must use a new version/base and preserve all earlier final-use markers. No final scoring is currently authorized by this inventory.

## Later explicit two-seed requirement

The new implemented scorer `score_frozen_architectures_final4096.py` supersedes the earlier single-candidate inventory: BOTH completed training seeds are primary replications at exactly the same frozen configuration, epoch and raw-or-EMA state. Epoch/state are selected from seed1 viewed-validation Top512 before final access, then applied to both seeds. Reports preserve each seed and their metric mean (not a logit ensemble and never best-seed selection). The other state is secondary only when predeclared. A runtime gate verifies each exact checkpoint, CPU acceptance, completed training budget, source and actual seed identity, requires different actual training-plan SHA, common viewed G5 proof, and strict architecture binding before any final journal opens. Current first-seed-only and future-template descriptors fail this gate. Static E1 remains a one-seed reference.
