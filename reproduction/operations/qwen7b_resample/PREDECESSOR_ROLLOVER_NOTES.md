These are future-generation tools, not changes to the nine existing productive stages or the newly admitted GPU3 TP1 stage. No predecessor stop, new owner, new relay or new-generation model has been launched by preparing these files. `predecessor_generation_terminal.py` requires a freshly captured immutable node-local JSON plan plus its exact SHA. A plan contains run_id, node, source {unit,pid,birth}, ordered_units with each unit/node/pid/birth, borrows_units, optional allocation_path/allocation_sha256, and metadata_roots. It explicitly retains partial outputs and states that the old loops do not support a whole-batch drain marker. Never pretend a forced old-loop stop loses no partial work.

The producer verifies a plan read-only by default; only explicit --execute records a stop intent and performs the ordered stops. It checks each consumer is actually terminal before stopping an owner, and binds each local PID to its birth. Existing intent/proof is read-only and never replays signals. A source5 plan references the exact real node10 terminal proof/SHA, without querying node10 PIDs in source5 /proc.
