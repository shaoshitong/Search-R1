# Independent canonical raw and actor trace audit for formal1–200

This additional CPU consumer follows the real `actual-attempts.jsonl` history.
It authenticates historical1–5 against producer718650/source5816 and resumed
6–200 against producer719225/source1843. Startup authenticates only the already
completed prefix; future scope is not evidence of future completed training.
The healthy native4 producer and existing EA archive/final restore controller
remain on their original immutable sources.

Every normal-return attempt is retained by its original UUID and global attempt
index. Any positive actual Adam write count is a successful outer and commits
one scheduler advance and head update. A fully skipped attempt has zero writes,
no successful outer, no scheduler advance, and an aborted head transaction. Its
actual512×5 raw labels and private token trace are still audited. Logical201,
copied prefix rows, missing attempts, or a fabricated success are rejected.

Each attempt runs in a fresh CPU process bound to its original source. The raw
file is fully hashed and loaded through one descriptor, then used both to decode
strict terminal binary EM against canonical training question/text/gold and to
reconstruct the original actor trace. The consumer verifies G5, exploration64
plus top448 selection, K/mean/ddof1 standard deviation, prequential measurements,
the head transaction, ordered trajectory IDs, parent digests, all retained token
contexts, selected sampling probability projection, and eight-field actor rows.
Rebuilt private trace bytes must exactly equal the original private file. It
does not reload model weights, run an HF forward, generate, fit, update, submit
a job, or publish producer evidence. Large raw/token files stay remote.

Run the published immutable source's module
`reproduction.hpc3_qprobe.raw_audit_followthrough719225` with `--commit <SHA>` and
`--start` once. Use the same source and `--inspect` thereafter. The fixed control
directory is `ROOT/observations/raw-all200-719225-20261015`. Existing claims are
inspected and never replayed. The detached supervisor holds each direct child
until an actual wait result, retains birth/source/task receipts and output SHA,
and requires exit0 plus empty stderr before accepting a task. Input ledgers
being appended or a head receipt still being published cause a read-only wait.
Actual failure retains its claim, output and terminal result for diagnosis.

All CPU libraries are explicitly capped to one thread, CUDA visibility is empty,
bytecode is disabled, and tokenizer loading is local/offline. Terminal success
requires exact successful1–200, every normal-return attempt, and the corrected
independent full attempt transaction verifier. `goal_complete` remains false:
fixed validations, exact final51713 scoring, fresh three-copy checkpoint SHA and
actual final native4 restore/cleanup remain separate required acceptance.
